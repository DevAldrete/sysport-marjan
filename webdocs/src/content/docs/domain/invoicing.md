---
title: Invoicing & payments
description: How invoices are created, how status is derived, and how payments settle them.
---

Invoicing turns a delivered request into money owed, and payments settle it. The status is
**derived**, never hand-maintained.

## Creating an invoice — BR-20

`sp_create_invoice_from_request(request, issue, amount, user)`:

- the request must be `delivered` or `closed`;
- it must have `agreed_rate > 0`;
- it must **not** already have an invoice (`invoices.service_request_id UNIQUE`);
- the amount defaults to `agreed_rate` but can be overridden;
- the due date comes from `fn_invoice_due_date` (**BR-19**):
  - **cash** client → `due_date = issue_date`
  - **credit** client → `due_date = issue_date + credit_days`
- the invoice number (`INV-YYYY-NNNNNN`) is generated by `fn_next_invoice_number`.

The UI's "Por facturar" table (`sp_requests_pending_billing`) lists requests with an authorized
rate and no invoice yet (**FR-INV-1**).

## Derived status — BR-19

`fn_invoice_status(current, amount, paid, due, today)`:

```text
cancelled stays cancelled
paid      if paid ≥ amount
overdue   if due < today (and not fully paid)
pending   otherwise
```

`paid` is not stored on `invoices`; it is `SUM(payments.amount)` computed in `v_invoice`. So the
balance shown everywhere is always consistent:

```java
public BigDecimal balance() { return amount.subtract(paid == null ? ZERO : paid); }
```

Status is recomputed:

- on each payment (`sp_register_payment`), and
- in bulk by `sp_refresh_invoice_statuses` (**FR-INV-3**), triggered by the "Actualizar estatus"
  button.

## Payments

`sp_register_payment(invoice, amount, date, method, user)`:

- locks the invoice row;
- rejects a **cancelled** invoice;
- rejects `amount ≤ 0`;
- rejects **overpayment**: `paid + amount > amount`;
- inserts the payment;
- recomputes the invoice status.

Payment methods: `cash`, `transfer`, `check`, `card`, `other`.

Partial payments are allowed and accumulate.

## Cancelling an invoice

`sp_cancel_invoice` (**BR-19**) refuses to cancel:

- a `paid` invoice,
- an already-cancelled invoice, or
- an invoice that has any payments.

This prevents money from being stranded on a cancelled invoice.

## Balances & receivables

- `v_invoice` gives `amount`, `paid` and (in Java) `balance` per invoice.
- `sp_receivables` lists non-cancelled invoices with `balance > 0` (**FR-RPT-6**).
- The Invoices screen shows Importe / Pagado / Saldo and supports partial payments.

## Java entry points

| Action | Service method | Permission |
| --- | --- | --- |
| Create invoice | `InvoiceService.createFromRequest` | `invoices.write` |
| Register payment | `InvoiceService.registerPayment` | `payments.write` |
| Delete payment | `InvoiceService.deletePayment` | `payments.write` |
| Cancel invoice | `InvoiceService.cancel` | `invoices.write` |
| Refresh statuses | `InvoiceService.refreshStatuses` | `invoices.write` |
