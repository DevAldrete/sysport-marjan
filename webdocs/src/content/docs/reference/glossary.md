---
title: Glossary
description: Domain vocabulary used consistently across code, SQL and UI.
---

| Term | Meaning |
| --- | --- |
| **Service request** | A client's order to move cargo from A to B, identified by a folio. The central entity. |
| **Folio** | Human-readable unique request identifier, e.g. `SR-2026-000123`. Generated by `fn_next_folio`. |
| **Package / bulto** | One line of a request's cargo (description, quantity, unit, per-unit weight) in `request_packages`; a request may have many. |
| **Effective weight** | `fn_request_weight`: sum of a request's packages, or the manual `estimated_weight` when it has none. Used by BR-08. |
| **Trip** | The physical execution of a request with one vehicle and one operator. Created at assignment. |
| **Operator** | An employee who drives (an `employee` with a license). |
| **Employee** | Any staff member; operators are employees with a license. |
| **License** | A driver's license record with an expiration date that gates assignment. |
| **Route** | An origin → destination lane with an estimated distance. |
| **Rate** | A negotiated price for a client on a route, valid over a date range. |
| **`agreed_rate`** | The price **snapshotted** onto a request at authorization. Never recalculated. |
| **Advance** | Cash given to an operator before a trip, to be justified afterwards. |
| **Settlement / comprobación** | Comparing an advance against proven expenses (BR-16). |
| **Expense** | A per-trip cost typed by category (tolls, food, …). |
| **Fuel load** | A fuel purchase; its cost lives only in `fuel_loads` (no fuel expense). |
| **Delivery** | Proof of delivery for a trip: who received it and an evidence reference. |
| **Incident** | An operational event logged against a trip. |
| **Invoice** | The bill for a delivered/closed request. One per request in v1. |
| **Payment** | Money received against an invoice; partial payments accumulate. |
| **Receivable** | An invoice with an outstanding balance. |
| **Snapshot** | A value copied at a point in time so it never changes (e.g. `agreed_rate`). |
| **Eligible** | A vehicle/operator that passes the assignment checks for a date window. |
| **Overlap** | Two active trips whose planned windows intersect — forbidden per resource. |
| **Sweep** | The time-driven batch (`sp_sweep_lifecycle`) that advances the lifecycle. |
| **Sequence** | The `sequences` table row used to allocate an id. |
| **DOP** | Data-Oriented Programming: immutable data + pure functions over it. |

## Codes you will see

| Code | Meaning |
| --- | --- |
| `BR-xx` | A business rule (see [Business rules](/domain/business-rules/)). |
| `FR-xxx-n` | A functional requirement from the PRD. |
| `Dn` | A design decision from the PRD (§13). |
| `v_*` | A database view. |
| `fn_*` | A database function (pure). |
| `sp_*` | A stored procedure (a use case). |
| `ck_*`, `fk_*`, `uq_*`, `idx_*` | constraint / index names. |
